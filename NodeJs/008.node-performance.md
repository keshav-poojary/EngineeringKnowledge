**Node.js performance** is about how efficiently your app handles requests, CPU work, memory, and I/O. Since Node.js runs on a single-threaded event loop, performance tuning focuses on *non-blocking design, efficient async handling, and resource optimization*.

Here’s a clear, practical breakdown 👇

---

# ⚡ 1. Understand the Core: Event Loop

Node.js uses an **event-driven, non-blocking I/O model**.

* Great for: APIs, real-time apps, streaming
* Weak for: heavy CPU tasks (because it blocks the loop)

👉 Rule:
**Never block the event loop**

---

# 🚫 2. Avoid Blocking Code

### Bad (blocking)

```js
const data = fs.readFileSync("file.txt");
```

### Good (non-blocking)

```js
fs.readFile("file.txt", (err, data) => {});
```

Also avoid:

* Heavy loops
* Complex JSON parsing on huge objects
* Synchronous crypto/compression

---

# 🧠 3. Use Async Efficiently

Prefer:

* `async/await`
* `Promise.all()` for parallel tasks

```js
// Slow (sequential)
await task1();
await task2();

// Fast (parallel)
await Promise.all([task1(), task2()]);
```

---

# 🔥 4. Use Clustering (Multi-Core)

Node is single-threaded, but CPUs aren’t.

Use **cluster mode**:

```js
const cluster = require("cluster");
const os = require("os");

if (cluster.isMaster) {
  os.cpus().forEach(() => cluster.fork());
} else {
  // run server
}
```

Or simply use:

* **PM2**

```bash
pm2 start app.js -i max
```

---

# 🧩 5. Offload CPU Work

For heavy tasks:

* Use **Worker Threads**
* Use queues (BullMQ, RabbitMQ)

```js
const { Worker } = require('worker_threads');
```

---

# 💾 6. Optimize Database Calls

* Use indexing
* Avoid N+1 queries
* Use connection pooling
* Cache frequent queries

---

# 🚀 7. Add Caching

Use:

* **Redis** (most common)
* In-memory caching (for small apps)

Example:

```js
if (cache[key]) return cache[key];
```

---

# 📦 8. Use Streaming for Large Data

Instead of loading entire data:

```js
fs.createReadStream("bigfile.txt").pipe(res);
```

---

# 🧹 9. Memory Optimization

Watch for:

* Memory leaks
* Large object retention

Tools:

* Chrome DevTools
* `--inspect`
* Heap snapshots

---

# 📊 10. Profiling & Monitoring

Use tools:

* `console.time()`
* `clinic.js`
* `0x`
* `New Relic` / `Datadog`

---

# ⚙️ 11. Use Production Settings

```bash
NODE_ENV=production
```

Why?

* Disables dev checks
* Improves framework performance (like Express)

---

# 🧱 12. Optimize Middleware (Express)

Bad:

```js
app.use(heavyMiddleware); // runs for all routes
```

Better:

```js
app.use('/api', heavyMiddleware);
```

---

# 🧪 13. Load Testing

Use:

* `k6`
* `Artillery`
* `Apache Benchmark`

---

# 🧠 Quick Summary

* Don’t block event loop
* Use async + parallel execution
* Scale with clustering
* Cache aggressively
* Offload CPU-heavy work
* Monitor everything
