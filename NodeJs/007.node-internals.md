# 🚀 Node.js Deep Internals: Under the Hood Guide

A comprehensive guide to the architecture, threading model, and asynchronous mechanics of Node.js.

---

## 🏗️ 1. The High-Level Architecture
Node.js is a **C++ application** that embeds the **V8 Engine** and **Libuv**.

* **V8 Engine:** Developed by Google (C++). It compiles JavaScript into Machine Code. It handles the Call Stack, Heap memory, and Garbage Collection.
* **Libuv:** A multi-platform C library that provides support for asynchronous I/O based on an **Event Loop** and a **Thread Pool**.
* **C++ Bindings:** The glue that allows JavaScript to talk to the underlying C++ code (e.g., `fs` or `http` modules).



---

## 🔄 2. The Event Loop: Phase by Phase
The Event Loop is a 6-phase cycle that manages asynchronous callbacks.

### 1. Timers Phase
Executes callbacks scheduled by `setTimeout()` and `setInterval()`. Node checks if the threshold time has elapsed.

### 2. Pending Callbacks Phase
Executes I/O callbacks deferred from the previous loop iteration (e.g., specific TCP errors like `ECONNREFUSED`).

### 3. Idle, Prepare Phase
Used internally by Node for housekeeping. You will rarely interact with this.

### 4. Poll Phase
The most critical phase. 
* Node calculates how long it should block and poll for I/O.
* It executes scripts in the poll queue.
* **Crucial:** If the poll queue is empty, Node checks for `setImmediate()`. If one exists, it moves to the **Check Phase**.

### 5. Check Phase
Specifically for `setImmediate()` callbacks.

### 6. Close Callbacks Phase
Handles the closing of handles, such as `socket.on('close', ...)`.

---

## ⚡ 3. Microtask Queues (The "VIP" Queues)
Microtasks are **not** part of the Event Loop phases. They are executed **between** phases or even between individual callbacks within a phase.

1.  **`process.nextTick()` Queue:** The highest priority. Executed immediately after the current operation, before the loop moves to the next phase.
2.  **Promise Queue:** Executed after the `nextTick` queue but before the next Event Loop phase.

> **Interview Tip:** If you recursively call `process.nextTick`, you will starve the Event Loop, and I/O will never happen.

---

## 🧵 4. Libuv & Asynchronous I/O
How does Node handle I/O without blocking the single thread?

### A. Kernel Offloading (Epoll/Kqueue)
For **Network I/O** (HTTP, TCP, UDP), Node offloads the work to the Operating System kernel. The kernel notifies Libuv when the data is ready. This is extremely efficient and uses **zero** Node threads while waiting.

### B. The Thread Pool
For tasks where the OS doesn't provide an async interface (File I/O, DNS, Crypto, Zlib), Libuv uses its **Thread Pool**.
* **Default size:** 4 threads.
* **Customization:** `process.env.UV_THREADPOOL_SIZE = 64;`

---

## 📦 5. Module System: CommonJS vs ESM
* **Require (CJS):** Synchronous. Wraps code in a function: `(function(exports, require, module, __filename, __dirname) { ... });`.
* **Import (ESM):** Asynchronous. Uses a "static" approach, allowing for Tree Shaking (removing unused code).

---

## 🧪 6. Multiprocessing: Scaling Node
* **Worker Threads:** Shares memory. Best for CPU-intensive tasks (e.g., Image processing).
* **Child Process:** Separate memory. Good for running CLI tools or scripts.
* **Cluster:** Spawns multiple instances of the same server to share the load across all CPU cores.

## 🔥 Top Interview Questions (Technical Deep-Dive)

### Q1: Is Node.js truly single-threaded?
**Answer:** The **JavaScript execution** is single-threaded (one Call Stack). However, the **Node.js Runtime** is multi-threaded. Libuv opens multiple threads for File I/O and Crypto, and the V8 engine uses threads for garbage collection.

### Q2: Explain the difference between `setImmediate` and `setTimeout(fn, 0)`.
**Answer:** - `setTimeout(fn, 0)` runs in the **Timers Phase**.
- `setImmediate(fn)` runs in the **Check Phase**.
- If called inside an I/O callback (e.g., `fs.readFile`), `setImmediate` **always** runs first because the Check Phase follows the Poll Phase immediately.

### Q3: What happens if the Thread Pool is full?
**Answer:** Further asynchronous tasks (like `fs.readFile`) will be queued until a thread becomes available. This can cause latency in File I/O performance while Network I/O (handled by the Kernel) remains fast.

### Q4: How do Promises work "Under the Hood"?
**Answer:** Promises are a V8 feature. When a promise resolves, its `.then()` is pushed to the **Microtask Queue**. The Event Loop checks this queue after every single operation in a phase before moving forward.
